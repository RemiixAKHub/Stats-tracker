COLLECTIONS ASSISTANT — DEVELOPMENT ROADMAP
==============================================

Purpose
-------
Build a streamlined Collections Assistant Sidebar to reduce call wrap-up
time and make frequently required information and process checks easier
to access while working alongside C4C.

The existing sidebar is the working baseline. The current tracker has a
70% maximum process contribution because some elements of the eventual
QM assessment cannot be marked by the sidebar during the call. The
remaining QM assessment is completed by management.

IMPORTANT SCOPE PRINCIPLE
-------------------------
Focus only on things the agent can control, check, record, or complete
during the call.

Do NOT attempt to score or track subjective QM observations such as:
- Tone
- Pace
- Rapport
- Active listening
- Whether the agent overtalked
- Whether language sounded sincere

These remain outside the sidebar's scoring system and are assessed by
the manager/QM process.

CURRENT BASELINE
----------------
The existing HTML sidebar contains:
- Process Contribution score (70% maximum)
- Fundamentals checklist
- Outcome & Future checklist
- Manual call notes box
- Copy Notes button
- Reset All button
- Reminder for Credit File and PSR

The existing 70% calculation should be retained as the foundation rather
than removed.

CORE PRODUCT GOAL
-----------------
Reduce the time between:
    Call ends -> notes completed -> C4C updated -> call wrapped

Target workflow:
    Track required actions during call
        ->
    Capture structured information
        ->
    Automatically build the call note
        ->
    Check outstanding required actions
        ->
    Copy final notes
        ->
    Wrap call

DEVELOPMENT PHASES
==================

PHASE 0 — BASELINE & SAFETY
----------------------------
Status: COMPLETE / BASELINE EXISTS

Objectives:
- Preserve the current working tracker.
- Keep a fallback copy of the original HTML.
- Treat the current sidebar as the starting prototype.
- Avoid unnecessary changes to unrelated systems.
- Keep the first versions standalone and local.
- Do not depend on AI for core functionality.

Success criteria:
- Existing tracker remains usable.
- Any experimental feature can be removed without losing the baseline.

PHASE 1 — QM-AWARE TRACKER
---------------------------
Status: COMPLETE

Objectives:
- Keep the existing 0–70% process contribution.
- Reorganise the checklist into logical workflow sections.
- Make each checklist item correspond to something the agent can
  actually control or verify.
- Improve visibility of incomplete items.
- Add a clearer call progress indicator without replacing the 70% score.

Suggested sections:
1. Customer / Security
2. Account / Collections
3. QM-Controlled Process Behaviours
4. Resolution
5. Wrap-Up

Potential controlled items include:
- Customer data checked
- DPA completed
- Balance discussed
- Payment requested
- Reason for non-payment
- System investigation
- Credit file checked
- Vulnerability / PSR checked
- Affordability assessed
- Appropriate resolution identified
- Account action / follow-on
- Correct information / escalation
- Timescales / self-service
- Debt recovery / reminders
- DD Guarantee + TW on Bill
- Correct tickets / notes
- Summary completed
- Next steps confirmed

Note:
The exact checklist should be based on the user's real operational
process and QM material. Do not invent requirements where the source
material does not support them.

QM SCORING MODEL
----------------
The sidebar should continue to represent the controllable portion of
the process as a maximum of 70%.

Conceptually:

    QM PROCESS CONTRIBUTION
    0% — 70%

The remaining portion is not something the sidebar attempts to score.
It is completed through the manager/QM assessment.

PHASE 2 — GUIDED CALL WORKFLOW
------------------------------
Status: COMPLETE

Objectives:
- Make the checklist useful during the live call rather than just at
  the end.
- Provide short contextual reminders linked to controllable behaviours.

Examples:
- Balance discussed -> reminder to make figures clear.
- Hold used -> reminder to explain what is happening.
- Resolution discussed -> reminder to explain the outcome.
- Call nearing completion -> prompt to summarise and confirm next steps.

Rules:
- Prompts must be short.
- Do not obstruct the call.
- Do not claim to measure subjective QM behaviours.
- The user remains in control.

PHASE 3 — STRUCTURED NOTES BUILDER
-----------------------------------
Status: COMPLETE

Primary objective:
Reduce wrap-up time.

Replace the reliance on manually typing the entire note with structured
inputs that can generate the user's approved note format.

Potential fields:
- Call type
- Reason for contact
- Reason for non-payment
- Number of occupiers
- Usage / tariff
- Account updates
- Account history
- Repeat contact
- PSR
- Affordability
- Payment made
- Plan set
- Additional information
- Timescales advised
- Credit file advised
- Debt recovery advised
- Next steps

Workflow:

    Enter/check information
            ->
    Generate Notes
            ->
    Review
            ->
    Copy Notes
            ->
    Paste into C4C

Success metric:
The user should spend substantially less time manually constructing
wrap-up notes.

PHASE 3.1 — QM GUIDANCE TOGGLE
-------------------------------
Status: COMPLETE

- QM Quick Prompts can be switched ON/OFF.
- Preference is remembered locally.
- Turning guidance off does not affect scoring or checklist completion.

PHASE 3.2 — CALL-TYPE / OUTBOUND REFINEMENT
--------------------------------------------
Status: COMPLETE / REFINED

- Inbound and outbound workflows supported.
- Outbound has a fixed calling reason.
- Outbound has its own outcome options.
- PSR supports Yes / No / N/A.
- Call type is intended to persist through Reset.

PHASE 4 — WRAP-UP VALIDATOR
----------------------------
Status: PLANNED

Objectives:
Before the call is considered complete, show what is still missing.

Example:

    CALL READY
    9 / 12 complete

    Still outstanding:
    - Summary
    - Next steps
    - Debt recovery advice

Also show note status:
- Notes not generated
- Notes generated
- Notes copied

The validator should focus on missing controllable actions, not QM
subjective judgement.

PHASE 5 — CUSTOMER / ACCOUNT SNAPSHOT
--------------------------------------
Status: IN PROGRESS

Objective:
Reduce the need to switch between screens.

Potential information:
- Customer name
- Account number
- Balance
- Account status
- Collections stage
- Property
- Postcode
- Occupiers
- PSR
- Last payment
- Relevant account information

IMPORTANT:
Do not assume this information can be automatically retrieved from C4C.
First establish what information is technically accessible and what
the work environment permits.

Initial implementation may use:
- Manual entry
- Paste-in information
- User-controlled fields

Later versions may investigate read-only browser integration.

PHASE 6 — PAYMENT BEHAVIOUR SUMMARY
------------------------------------
Status: PLANNED

Objective:
Make useful account/payment history easier to interpret.

Possible deterministic calculations:
- Most recent payment
- Average payment
- Typical payment amount
- Payment frequency
- Typical payment day
- Broken arrangements

Do not introduce speculative customer predictions unless there is a
clear, defensible rule and an approved reason to use it.

PHASE 7 — C4C / BROWSER INTEGRATION
------------------------------------
Status: FUTURE

Objective:
Reduce manual copying and screen switching where technically and
operationally appropriate.

Potential investigation:
- Read relevant information from the C4C page.
- Detect the account currently being viewed.
- Populate the sidebar from visible information.
- Provide safe read-only assistance.
- Potentially streamline copying or navigation.

This phase must come after the standalone assistant is stable.

Do not build around assumed C4C capabilities.

PHASE 8 — OPTIONAL AI ASSISTANCE
---------------------------------
Status: FUTURE / OPTIONAL

AI should enhance the tool, not be required for core operation.

Potential uses:
- Turn rough notes into the approved note structure.
- Help structure free-text information.
- Identify potentially missing controllable information.
- Provide contextual assistance.
- Potential future transcript-assisted support if an approved and
  technically accessible transcript source exists.

Core checklist, calculations, note templates and wrap-up functions
should continue to work without AI.

VERSION STRATEGY
================
V1 — QM-Aware Tracker
- Improved checklist
- Existing 0–70% contribution
- Clear incomplete items
- Better workflow layout

V2 — Wrap-Up Assistant
- Structured note fields
- Automatic note generation
- Copy-ready output
- Wrap-up validation

V3 — Account Assistant
- Customer snapshot
- Account information
- Payment history tools

V4 — C4C Integration
- Investigate safe browser integration
- Reduce manual information transfer

V5 — Optional Intelligence
- AI assistance where it provides measurable value

DESIGN PRINCIPLES
=================
1. Wrap-up time is the primary success metric.
2. The sidebar should reduce screen switching.
3. Keep core functionality deterministic and reliable.
4. Only track things the agent can actually control or verify.
5. Do not attempt to score subjective QM observations.
6. Keep the 70% controllable-process concept.
7. Do not invent operational requirements.
8. Minimise changes outside the requested feature.
9. Preserve a working fallback version.
10. AI is optional; the core tool must work without it.
11. Build in small phases and test each phase before moving on.
12. Never assume C4C data is accessible until technically verified.

DO NOT LOSE THIS PRINCIPLE

process consistently and finish the call faster.

The manager/QM assessment remains responsible for the parts that cannot
be reliably marked by the sidebar.
